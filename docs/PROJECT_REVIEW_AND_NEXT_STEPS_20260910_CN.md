### P1：先纳入已有机制对照，再选择缺失的组件消融

一个有解释力的具体问题是：**两个分支共同选择同一支持 patch，是否比各自独立寻找最近邻更有效？** 当前正文已经解释这两种操作的区别，后来的 R1 `MAP_mean` 也已经做了相应真实数据对照；应把新实验整合进稿件，不再把它列为完全未做的工作。

设每个分支描述子已归一化，且支持 patch 身份与网格对应；记两分支的余弦距离为 d_D、d_C。等权拼接并联合归一化时，对单个查询 patch 的距离为：

```text
联合检索：s_joint(q) = min_m [0.5 d_D(q,m) + 0.5 d_C(q,m)]
独立检索：s_late(q)  = 0.5 min_m d_D(q,m) + 0.5 min_n d_C(q,n)
```

二者区别是是否允许两分支用不同正常 patch 解释同一个查询。相同条件下，平滑前有 `s_joint >= s_late`，但这并不推出联合检索的 AP 更高。R1 使用同一冻结缓存及后处理，分别计算 DINO / CLIP 最近邻距离再求均值；相对 A1，K=2/4 的宏平均 ΔPixel-AP 为 **+0.005517 / +0.003942**，最差类别为 **−0.011574 / −0.016827**。这说明独立检索平均在这两个开发配置上反而有小幅平均收益，但达不到 +0.01 门槛，不能证明 A1 的共同匹配机制普遍更优，也不足以晋升为新主线。[R1 实现](D:/STUDY/My_github/sci_project/scripts/innovation_breadth_20260908/probe_breadth.py:142)

最小下一步是引用这项已有结果，注明 seed=0、MPDD 六类和双 shot 的范围；只有需要更广主张时才扩展配置，并可增加最近邻身份分歧诊断。它适合作为现有论文的机制说明，而非“首次提出”的新算法。另一个容易误写的地方：两分支已经单位归一化且固定等权时，最终联合 L2 只是固定范数缩放；单独去掉它通常不会改变排序，不能把这种等价变换包装为性能贡献。[实现依据](D:/STUDY/My_github/sci_project/scripts/evaluate_a1_feature_fusion.py:96)

其他消融按论点选择，不必全做：分支归一化、CLIP 网格对齐方式、DPAM 特征来源。每次只改变一个有实际数值作用的因素，出现退化也如实报告。

- **AP 与类别不平衡：** 高 AUROC、低 AP 不能直接证明“排序已经接近最优，只剩基率问题”。结合正常图误报、缺陷尺寸、对象/背景区域、不同缺陷类型检查错误排序；掩码可以用于事后诊断，不能悄悄回流到选参。
- **统计解释：** 已有 bootstrap，无需从零建立统计系统。要明确各区间针对类别重采样、图像重采样还是异常图像子集；估计对象不同就分别标注，不能把某个子集 CI 当作全测试集 AP 的 CI。
- **运行成本：** 当前稿已经说明阶段耗时求和及其倒数不是端到端生产吞吐。若正文继续主打可部署性，补一次包含两编码器、传输、检索及后处理的实测，报告硬件、预热、批大小、峰值显存/内存和延迟分布。
- **新验证集角色：** BTAD、MVTec 的历史冻结验证结论仍然保留；它们如今已被查看，不能在下一轮选参后再次被称为全新盲测。新的方法应先冻结，再在未参与选择的类别或新数据上验证。
- **逐类数据统计：** 当前正文已有总量，但逐类正常/异常图数量与原始分辨率分布仍应由实际 split manifest 生成补充表。这能帮助解释类别不平衡和小缺陷问题，也防止不同实验使用的样本范围被误认为完全一致。

### P1：让复现材料真正可交给另一台机器

当前 compact 包有独立 CPU 实现，可以用保存的 patch map 和合法获取的 mask 复算指标；完整 GPU 路线则还依赖本机被 Git 忽略的 `methods/` 第三方源码。两条路线的可用范围应分别写明。实际源码与 compact 独立实现均为先 resize 再 Gaussian，本轮没有发现两者操作顺序不同。

环境 freeze 中含本机绝对 wheel 路径，权重也引用本机缓存；它们是有价值的历史环境快照，但不是外部机器可直接安装的依赖锁定文件。最小交付应补齐第三方固定提交、权重校验、wheel 官方获取方式、双环境安装顺序，以及 CPU / GPU 各自最小命令。无需因此重导出全部特征。

历史 81、122、123、141 个测试通过记录来自不同时间或范围，其中也存在文档不一致。统一一份带日期、解释器及明确 `tests` 范围的记录即可，不要把这些数字混成当前 HEAD 的验收结果。另应把较新的 MPDD / BTAD 许可核查同步到正式发布说明；冻结旧包保留历史身份，正式 release 使用新的文件清单与哈希。详细入口和差异见 [复现审计附录](D:/STUDY/My_github/sci_project/docs/project_review_20260910/repro_audit.md)。（**2026-09-20 追注**：测试计数已收敛——仓库根新增 `pytest.ini` 界定正式范围，实测 260 passed / 0 failed；`141/141` 已就地标注为历史快照。见 `tests/README.md`。）

## 4. 创新突破：保留哪些方向

以下均为待检验假设，优先级是基于当前证据的研究判断，不是正结果保证。前三项最值得小规模试探；后两项适合作为条件允许时的扩展。进入正式方法之前仍需单独检查与现有工作的差异。

| 方向 | 与已失败小变体的实际区别 | 第一步怎样点到即止 | 何时停止 / 扩展 |
|---|---|---|---|
| 真实变换下的等变对齐与正常覆盖 | 对原图做有物理意义的变换，再重新提取特征并逆变换对齐；区别于移动现有 patch 网格 | 仅用允许的支持图像，测试 1–2 种保持缺陷语义的变换；对照同计算量的重复/普通增强 | 若只在合成缺陷上有效，或几何边界出现伪影即停止；真实类别稳定后再扩 |
| 对象 / 部件约束的上下文匹配 | 引入部件身份、结构关系或前景先验，限制跨背景的错误正常匹配；区别于对异常图做区域均值池化 | 先在已知困难类别分析最近邻是否跨部件，再比较全局 NN 与部件内 NN；同时计入分割成本 | 若先验本身不稳定，或只是借用额外大模型带来的表征收益，不能宣称提出了独立新机制 |
| 新表征的互补性筛选 | 新的编码层、训练来源或分辨率必须提供现有两分支缺少的信息；不是对现有分数再加权 | 先做单分支及错误重叠诊断，再选一个互补分支做严格融合对照 | 单分支没有新信息或组合持续损害正常区域精度，就停止；已有同类层融合负结果不重复扫 |
| 正常支持约束下的选择可靠性 | 研究支持样本变化导致的失败，目标是可观测的稳定性依据；不是用测试 AP 挑最优路由 | 在训练正常池的合法预算下做留一与参考集扰动诊断；先检验可观测量是否预测真实退化 | 只有真实泛化关联成立才建模块；K=1 的可识别性和增加正常数据的预算必须说明 |
| 面向成本的检索或缓存系统 | 目标直接设为资源—精度折中，允许 AP 基本持平 | 同结果口径实测磁盘、峰值内存、建库时间、检索时间及端到端延迟 | 只有存储节省就作为工程结果；若端到端成本无优势，不包装为加速算法 |

部件匹配与图结构已有 UniVAD 等工作，新表征和增强也有大量先例。因此潜在创新必须落实为可区别的约束、建模方式、适用条件及实证，而不是“加入分割模型”“换更大编码器”本身。[相关已有机制](https://github.com/FantasticGNU/UniVAD)

新数据和新任务也有价值，但更适合作为验证上述假设的环境：例如逻辑/关系缺陷需要明确当前像素定位任务是否足够描述问题。新增数据集不能直接算算法创新，也不能为了找到好结果不停换测试集。

### 建议统一的小门槛

保留既有小门槛的透明性：在 MPDD 开发实验的固定 seed=0、K=2/4 上，同时检查宏平均 ΔPixel-AP、最差类别变化与 ΔPixel-AUROC。历史广度探索采用的要求为两种 shot 均满足宏平均 ≥+0.01、最差类别 ≥−0.03、ΔPixel-AUROC ≥−0.005。

这只是开发筛选，不是显著性证明，也不是最终接受标准。新研究若目标转为成本或特定缺陷类型，应在看结果前另定相应指标，而不是事后改门槛使候选通过。通过小门槛后才扩展 seeds、K=1、完整类别和新的冻结验证；失败后记录原因并停止该具体配置族。

## 5. 建议停止继续投入的工作

- 仅在现有缓存上反复尝试全局权重、排序混合、局部密度归一化、任意距离替换、区域均值平滑，且没有新失效假设的搜索。
- 把跨类别最差退化很大的宏平均提升选成主线，或只保留获益类别。
- 把合成小实验、代码可运行、缓存容量减少、某一张热图更好看，直接升级为真实数据上的方法有效性。
- 为了追求创新命名，重新包装固定拼接、严格单调的最终分数变换或简单常数缩放。
- 继续重画多个互相竞争的“最终主图”，却不把一套图与当前正文、图注和符号统一。

这些停止建议是资源分配判断，针对已经查过的设置；不等于从数学上否定这些研究领域。
