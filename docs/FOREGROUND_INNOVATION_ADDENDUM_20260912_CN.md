# AI 辅助评审建议的主体增强方向：判断、实验与交接补充

日期：2026-09-12。状态：**研究建议与待执行协议草案；本次仅核查已有代码、结果和文献，没有运行新的算法实验。**

配套任务书：[AI 实验交接与验收](<repo-root>/docs/AI_HANDOFF_VALIDATION_AND_INNOVATION_20260911_CN.md)。最新已执行记录：[交接轮结果](<repo-root>/experiments/dynamic_fusion/validation_handoff_20260911/FINAL_REPORT_CN.md)。本补充作为 E7 的新候选方向，**不修改已冻结协议、历史判定或结果文件**；运行前另立 `E7-F` 协议及输出目录。

## 1. AI 辅助评审和用户的想法

AI 辅助评审提出：能否在图像处理的最开始突出主体、弱化背景，使后续模型更容易学习或判断，从而降低负担、提高效果？

这个想法包含三个独立问题，实验必须分别回答：

1. 背景变化是否是当前误报的重要来源？突出主体能否提高异常检测与定位？
2. 同样的输入分辨率下，让主体占据更多有效像素，能否改善微小缺陷表征？
3. 减少背景 patch、记忆库或编码器 token 后，能否降低真实运行成本？

**判断：值得优先做一次有明确对照的小试验，但目前没有证据保证提升，也不能将普通去背景直接写成新算法。** 当前 A1 在目标数据集上不进行梯度训练，主要可能受益的是表征、正常参考建库和最近邻匹配。“减轻训练压力”若指学习收敛，需要另一个确实有训练的实验协议，不能用 A1 的测试时间代替。

## 2. 与项目已有工作是什么关系

冻结 A1 的主体流程是完整图像预处理、DINO-B / CLIP 视觉特征提取、对齐拼接、正常 patch 最近邻检索。它没有在输入 RGB 图上显式分割主体并弱化背景。

**但项目并非完全没有做过前景处理。** 最新交接轮的 `N_B_pcv` / `N_S_pcv` 使用 PCA 前景掩码，在已导出的 DINO 特征上进行筛选与评分。已有结果如下，均为 MPDD 六类、reference seed 0、K2/K4 的宏 P-AP 均值：

| 单分支 | 不加该掩码 | 加该硬掩码变体 | 差值 |
|---|---:|---:|---:|
| DINO-B | 0.338797 | 0.313435 | −0.025363 |
| DINO-S | 0.315717 | 0.322206 | +0.006489 |

数据来自 [E1 逐配置指标](<repo-root>/experiments/dynamic_fusion/validation_handoff_20260911/E1/metrics_per_config.csv)，实现入口为 [受控矩阵脚本](<repo-root>/scripts/validation_handoff_20260911/run_controlled_matrix.py:79)。这是**具体硬筛选实现的结果**，不等于所有主体处理失败，也不是 A1 双分支输入增强的实验证据。该变体同时提供另一种图像聚合分数；讨论上表像素指标时，不把图像聚合方式当作像素变化原因。

另一个 `official_native_B/S` 单元明确关闭了 masking 和 rotation，不能把它的结果当作“官方前景方法已完整验证”。见 [官方推理适配器](<repo-root>/scripts/validation_handoff_20260911/e1_native_official.py:66)。

旧 [E7 未触发记录](<repo-root>/experiments/dynamic_fusion/validation_handoff_20260911/E7/DECISION.md) 将缺少可部署部件分割方法列为限制。接手者应区分：**已有粗前景 PCA 入口，不等于已有可靠多部件分割系统；缺少 SAM 等新权重，也不等于不能先做粗前景诊断。** 先查明旧掩码的失效方式，再决定是否引入新分割器。

## 3. 为什么可能有效，以及哪里容易出问题

可能有效的机制是：少量正常支持图覆盖不了背景光照、阴影、纹理变化；查询背景找不到相似正常 patch，形成高分误报。主体裁剪还可能提高小缺陷在固定 token 网格中的占比。这些目前都是待验证解释。

必须保留的反例：

- **缺件、缺口：** 原本应有材料的位置可能被分割器识别为背景，恰好删掉异常证据。
- **边缘、孔洞和细小结构：** 硬掩码可能切掉裂纹、连接器引脚或孔洞附近缺陷；平滑轮廓不等于保住缺陷。
- **主体外异物：** 是否属于检测对象取决于任务定义，不能预先认定所有背景异常都无关。
- **满幅纹理：** 如木材、织物等，画面本身就是检测主体，强行前景分割可能没有意义。
- **小样本不稳定：** PCA 的方向、尺度和阈值可能随图像或骨干变化；对 S 有效的阈值不能默认迁移到 B。

前景分数应表示“应当检查的对象或区域”，不能直接用“像正常样本的程度”代替，否则越异常的区域越容易被丢掉。只依据查询图的可见主体生成区域也无法保证发现缺件；后续若研究正常支持区域与查询区域的联合约束，需要单独解决配准和预期占位问题。

## 4. 先选哪一种实现

| 层级 | 做法 | 回答的问题 | 主要限制 |
|---|---|---|---|
| 结果层 | A1 异常图按主体置信度软抑制背景 | 单纯压低背景分数是否足够 | 不改善已提取特征，通常不省编码器计算 |
| 输入层 | 保持尺寸与主体位置，背景适度模糊，边界平滑过渡，再提取两分支特征 | 减少输入背景干扰是否改善表征 | 需要重新编码；模糊伪影、漏分割可能伤害缺陷 |
| 输入层 | 带留边的主体 ROI 裁剪、等比缩放和 padding | 主体占比、有效分辨率是否是瓶颈 | 可能裁掉结构异常；固定输入尺寸不自动加速 |
| 检索层 | 前景查询优先匹配正常前景，边界/不确定区域使用全库回退 | 跨背景错误匹配是否是瓶颈 | 已有相关方法，规则错误会减少必要近邻 |

**建议顺序：先诊断旧硬掩码，再做“同尺寸输入软处理”与“结果层软处理”的直接对照；ROI 裁剪用于分辨分辨率效应。** 检索约束作为下一阶段的独立机制，首轮不把输入增强、裁剪、门控、检索一起叠加。

可作为输入软处理的最小定义：在原图坐标上生成 `m ∈ [0,1]`，令 `w = ε + (1−ε)m`，得到 `I_soft = w·I + (1−w)·blur(I)`。主体内部保持原图，边界平滑，背景保留残余。`ε > 0`、模糊半径、mask 膨胀量在看测试指标前固定。保留残余只能减轻风险，**不是不漏检的数学保证**。

这是普通预处理基线，不预先命名为原创方法。首轮只锁定一个前景生成器、一个软处理设置和一个 ROI 留边设置；若需要探索，连同默认设置最多三组，并完整报告。不要首轮同时下载多种大型分割模型。

若用 DINO 本次前向后的特征生成 mask，再对 RGB 图处理重编码，这是**两阶段推理**，必须计入第二次前向。若只是复用特征筛选，则不属于AI 辅助评审所说的输入端处理。

实现时还要避免一个无效操作：给某个 patch 的整条特征乘正标量后立刻逐 patch L2 归一化，标量会被抵消。不能把这种没有改变匹配的操作称为有效的前景加权；需要明确权重实际改变的是输入、token 交互、候选近邻还是异常分数。

## 5. E7-F 最小实验安排

### F0：先检查掩码和误报位置

先复用正常支持图与缓存检查 PCA 掩码，逐图保存 mask 面积、边界、异常分数叠图、空 mask / 全图 mask 比例。核查 PCA 输入是否被 L2、PCA 符号和数值尺度、二维形态学处理、坐标对应、空库回退。不能仅通过“脚本能运行”就认为 mask 正确。

分别检查正常图高分区域是否集中在真实背景，以及缺陷区域有多少落在低前景置信度区域。**缺陷 GT 的补集包含正常主体和背景，不能直接称为背景。** 严格背景误报分析需要独立主体标注；若只用自动 mask 分组，名称必须是“预测前景 / 预测背景”，并承认 mask 错误会影响诊断。少量人工主体标注只能用于冻结方法后的评价，不进入预测器或按测试表现调参。

正常图误报率高只能说明存在误报，不能单凭这一点确定背景是原因。诊断得出背景不是主要来源时，允许关闭这一方向并交付负结果。

### F1：固定六组，分清收益来源

默认使用同一冻结 A1、相同支持 ID、MPDD 六类、s0 K2/K4。首轮为六组 × 六类 × 两个 shot，共 72 个方法–类别–配置单元；可合法复用原 A1，但不得把缓存复用写成模型重跑。

| ID | 处理 | 必要目的 |
|---|---|---|
| F-A | 原图 A1 | 冻结基线 |
| F-B | 原图 A1 + 同一 mask 的结果层软抑制 | 隔离简单分数处理效果 |
| F-C | 同尺寸输入软处理 + A1，输出不另乘 mask | 对AI 辅助评审输入端假设的直接检验 |
| F-D | 同 F-C，但 mask 作预登记的空间错位 | 检查是否只是通用模糊/正则化；保持 mask 面积和处理强度 |
| F-E | 原 RGB 图主体 ROI + A1，不额外软处理 | 检查主体放大效应 |
| F-F | 原 RGB 图固定中心 ROI + A1 | ROI 简单对照；按支持图主体占比锁定裁剪尺度，不用测试指标定范围 |

F-D 使用固定的坐标变换与随机种子，禁止从多个错位结果中选择最差者。必须记录其与正确 mask 的重叠，重叠过高则该控制没有辨识力，不能声称已经支持主体对应机制。F-E/F-F 记录实际放大倍率与保留面积；尺度未匹配时只能报告“裁剪策略的整体差别”，不得将全部差值归因为定位准确。

支持图和查询图采用同一个处理算法，分别从自身图像获取 mask；K 仍表示独立正常原图数。两视觉分支使用相同原图 ROI，再各自 resize / normalize，记录从原图到各分支网格的坐标映射。F-C/D/E/F 必须处理真实 RGB 图并重新提取特征，不能在旧缓存上乘 mask 冒充输入实验。

所有预测回到原有完整 448×448 评价画布。裁剪外区域不能从指标中删除，也不能将 GT 裁剪后换一个更容易的任务。首轮 F-E/F-F 对裁剪外区域使用同一原图 A1 分数回填，内部和接缝采用预先固定规则；因此它们是带全图回退的准确率对照，**不能宣称单次前向或节省计算**。如后续要去掉全图回退，需要新的成本与漏检验证。

纹理类、不可靠 mask、多物体和空 mask 必须有事先规定的回退，例如整图 A1；不能在看到测试 AP 后手工决定某类启用模块。每次回退保存原因，计入总结果和耗时。

### F2：只有可信信号才扩大

F-C 为本轮主要假设候选，F-E 为主体尺度的探索对照；事先声明，不能看完六组后将最好的重命名为原假设。F-C 的核心比较是 F-A / F-B / F-D；F-E 的核心比较是 F-A / F-F。

真实开发门先复用主任务书 G0、G1-A：K2/K4 各自相对 A1 宏 ΔP-AP ≥ +0.01，最差类别 ≥ −0.03，宏 ΔP-AUROC ≥ −0.005。输入端机制进一步要求 F-C 相对 F-B **及** F-D 在两个 shot 各自宏 ΔP-AP ≥ +0.005，并保存逐类变化与不确定性。该附加数值是新建议的筛选门，不是统计定理；运行前写入 `E7-F` 协议并冻结。

F-C 未通过但 F-B 提升时，结论应是“结果层背景抑制有价值，尚未支持输入表征改善”；仅 F-E 提升时，先检查是否主要来自放大效应。若 F-E 意外成为后续主候选，需要新的确认阶段声明，保留它是开发阶段选出的事实。

通过后才按主任务书 G2/G3 扩 reference seed、shot 和冻结迁移，固定正确的简单对照一起扩展。后续机制比较相对上述对应简单对照：G2 平均 ΔP-AP 至少 +0.005，G3 各数据集平均不为负；其余类别保护与完整性标准沿用原任务书。BTAD/MVTec 不用于挑 mask 或留边参数。

## 6. 如何验证“减轻压力”

- **统计建模负担：** 用背景误报、缺陷与非缺陷分数分离、跨背景扰动稳定性检验。只能写相关证据支持，不能把热力图好看当作证明。
- **内存与检索负担：** 报告实际正常库 patch 数、字节数、建库时间、检索耗时。删掉背景 patch 可能缩库，但历史 coreset 失败说明不能假定减少 patch 无损。
- **编码器负担：** 若仍以 448 / 518 输入普通稠密 ViT，涂黑、变暗或模糊背景不减少 token 数，通常不降低主要前向计算量。真正减少 token、输入尺寸或调用次数，才另测准确率—成本关系。
- **训练负担：** 若以后训练适配模块，需要固定数据、初始化、优化器、迭代预算，比较学习曲线、达到同一验证标准所需步数和总时长；另立训练协议。当前 F1 不回答这一问题。

计时必须包含前景生成、可能的粗到细重编码、两视觉分支、匹配、坐标还原和回退。同步 GPU，预热后报告同硬件下 p50 / p95 与峰值 GPU/RAM。只报告“记忆库小了”不能推出“端到端更快”。

首轮把准确率作为主目标；若之后改以效率为主，先另定非劣界和成本门，不能在准确率失败后事后改称效率成功。

## 7. 论文创新性如何判断

相关工作已经覆盖部分想法：

- [AnomalyDINO 原论文 §3.2](https://arxiv.org/html/2405.14529v2)：利用 DINO 特征的 PCA 前景掩码减少无关区域误报，并明确讨论掩码失效；这与粗前景筛选直接相关。
- [UniVAD，CVPR 2025](https://arxiv.org/abs/2412.03342)：使用组件分割、组件感知 patch 匹配及组件关系建模；“分割再匹配”本身已有先例。
- [FB-CLIP，2026-03-20 预印本](https://arxiv.org/abs/2603.19608)：摘要已描述视觉侧多视角软分离和背景抑制。当前仅核查其摘要，尚未逐公式复现；不得宣称与其完全相同或已证明不同。

以上足以说明“强化前景 / 弱化背景”不是空白领域；本次检索也不是完整新颖性审查。增加现成分割器后取得增益，可以是有效工程改进，但算法创新还需要具体机制、必要性对照和文献差异。

更值得考察的具体问题是：**在前景分割不可靠、参考样本极少的情况下，怎样减少背景干扰，同时保住边缘、缺件和不确定区域的异常证据？** 可进一步研究依据分割不确定性保留上下文、主体与边界使用不同匹配规则，或支持图的预期占位与查询前景联合约束。它们目前都是假设，不是已成立的新颖贡献，也不要首轮同时展开。

还要验证模块在 DINO 单分支上是否同样有效。如果去背景后单分支已经达到增强 A1 的水平，应如实报告，并重新判断双分支必要性。候选通过 F1 后增加同输入处理下的 DINO-only、CLIP-only 对照，再解释是否存在融合互补。

## 8. 给接手 AI 的交付与停止标准

新建独立目录，建议 `experiments/dynamic_fusion/foreground_20260912/`，本次未创建实验产物。至少交付：

1. `PROTOCOL.json`：主假设、合法输入、mask 来源、checkpoint/代码哈希、全部设置、回退、坐标、预算、主候选、指标与门槛。
2. `mask_audit/`：主体 mask、边界/缺陷覆盖诊断、面积与失败统计；独立评价标注与自动分组明确区分。
3. `metrics_per_category.csv`、`metrics_per_config.csv`：六组完整结果，不能删除不利类别；预测图与输入 ID 可追溯。
4. `mechanism_and_cost.md`：收益来自输入、分数抑制还是主体放大；成本包括分割与额外前向；缺陷漏检和回退有案例。
5. `DECISION.md`：分别给出实验完成状态、性能门、机制证据、效率与创新性判断；未运行写未运行，阻塞写具体缺失。

掩码可靠性不成立时先修实现或关闭对应方案；出现明显缺件/边界漏检时不得只展示宏平均增益。完整 F1 无收益时停止该具体组合，不连续扫描阈值追求正结果。若只有某类有效，报告适用条件与代价，不能事后按测试结果制作类别路由。

本方向的“完成”是得到上述可复核答案，允许结论为无收益。AI 辅助评审的建议提供了值得测试的新输入假设；它不要求推翻既有负结果，也不保证形成论文主创新。
