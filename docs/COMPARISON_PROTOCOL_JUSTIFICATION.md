# 对照实验口径说明（2026-09-23 修订）

当前论文围绕表示、权重和正常参考匹配的受控归因展开。外部方法提供背景参照，不把不同原生或本地配置的结果解释成公平榜单。逐方法设置见新稿 Table S2，限制见 Discussion。

1. **受控比较**：除正在操纵的表示、权重或匹配规则外，支持清单、查询、几何和评估保持配对。配对 bootstrap 用于相应效应与交互，并不意味着所有外部表都做过配对显著性检验。
2. **外部共同区域表**：Table 11 是六个配置的冻结点值，Table 12 增加三个方法家族；统一的是原图共同有效区域与聚合规则，输入分辨率、骨干、增强与建库方式仍不同。PatchCore local128 是本地配置，不能与 224 配置一起笼统称为原论文配置。
3. **补充统一几何表**：Table S1 为短边 448、seed 0、K = 1 的五配置子集（36/144 单元）。只有 PatchCore 448 补跑，其余兼容预测复用；拉伸输入的三个家族不在其中。点值使用全网格，区间来自 stride-eight 像素，只计算 pixel AP 的边际 95% 区间；无跨方法差异检验。这一比较可复现，但仍不足以消除全部实现差异。统一分辨率不是“不可复现的新方法”。
4. **输出可比性**：外部比较使用连续定位图，不以“有的输出 patch、有的输出图像分数”作为不能统一评估的理由。图像级指标独立列在 Table 21，不能与像素 AP 混写。
5. **训练与稳定性**：实际配置在目标数据上不做梯度优化；预训练、辅助域 prompt 学习、参考库和 coreset 准备仍存在。没有目标域 loss–epoch 曲线。S4 只检验已存 bootstrap 估计的数值稳定性，不能代替所有方法在共同扰动下的性能稳定性实验。
6. **同机资源测试**：S5 的六配置使用同一 RTX 3060 Laptop、PyTorch 2.0.0+cu118 和 CUDA 11.8，但工作负载和输入协议不同。指标是阶段计时之和，含参考库工作，排除初始化、指标和写盘，不是独立测得的端到端墙钟或单图延迟。显存是进程内 PyTorch allocated peak；1 Hz 设备级监测另存。PatchCore128 首轮 30.527 s 与采用的重测 24.190 s 已披露。

主文保持简短说明，逐方法协议、补充几何表和配置敏感性图放补充材料。主线贡献为固定权重控制、表示与匹配交互定义、绝对表示价值与匹配敏感性分离的条件性发现。
