## 输出和示例的科学含义

模型真实输出是连续异常图 **A_t** 及图像级最大响应分数。轮廓由可视化阈值产生，不是额外学习到的输出，也不代表部署时已经确定固定阈值。

主图示例来自归档的 MPDD `metal_plate/test/scratches/026.png`，采用 A1、J、seed 0、K = 1。热图和红色轮廓来自同一预测；轮廓采用逐图归一化后的 256 档 Otsu 显示规则，没有使用测试真值掩码来设阈值。输入处多张缩略图用于表示一般 K 图输入，不表示这个 K = 1 示例实际使用了三张支持图。这些条件已写入论文图注和 PPT 备注。

J 和 L 分别表示共享正常参考与各分支独立参考。图中列出 A1、DUP、TRI、BAL 的权重，以及 E_TRI、E_BAL 与 I_TRI、I_BAL 的定义，突出本论文区分“重加权、增加表示、匹配依赖”的研究内容。额外分支是对照构造的选择，不是查询时动态切换的模块。

## 新增结果核查

表 11 从原来的点估计更新为已修复计算后的配对 bootstrap 区间。数据源为 `experiments/dynamic_fusion/limitation_closure_20260915/B_correspondence/` 中当前的 `interaction_by_variant*.csv` 与 `ot_sensitivity*.csv`，不使用修复前的备份。

每个设置采用 1000 个配对图像 bootstrap 重复，在重复内形成四项交互，再聚合类别和支持条件。表格报告观测条件均值及 98.75% 区间。MPDD 的 14 个区间均排除零，BTAD 的 14 个区间均跨零；校正覆盖每个设置的四项比较，不覆盖整个敏感性扫描的 28 格。论文已明确这一边界，并删除“区间不可得”的过期说法。

更细网格 BTAD 结果来自 `A_btad03_corrected/interaction_dataset_stride4.csv`；其 −0.011 和 −0.085 是 bootstrap 均值，已在正文标明，并标注对应 98.75% 区间。

## 性能实验尚待补齐的部分

冻结编码器方案在目标域没有优化器、训练轮次或目标训练 loss。因此目标 loss–epoch 收敛曲线应为 **N/A — no target-domain optimization**，不能用预训练曲线或虚构的零 loss 曲线替代。若比较训练型方法的收敛，只能另行使用那些方法的真实训练日志。

已有 A1 单条件测量中的 0.4146 s/image 是 DINO、CLIP、对齐/拼接/检索三个独立阶段均值之和，不是同时加载两个编码器后的完整端到端测量。参考 bank 的 MB 是特征存储量，不是峰值 VRAM。论文表 13 是部分外部方法的分阶段成本，缺少 A1 同口径完整时延和 PatchCore 进程 GPU 峰值。因此本次没有把这些记录包装成完整速度—显存排名图。

建议下一轮统一测量协议：

1. 使用同一设备、同一查询集合与支持 seed/K，记录各方法输入分辨率、精度和批量大小；模型加载与一次性建库单独计时。
2. 同一进程加载 A1 的 B+C 两分支，计入查询编码、对齐/融合、检索及后处理；缓存查询特征的结果另列，不能与完整推理混合比较。
3. 预热后进行 GPU 同步计时，保存逐图延迟，报告均值、p50/p95 和吞吐。明确是否包含图像读取与预处理。
4. 重置并记录完整流程的 peak allocated/reserved VRAM，并辅以进程 GPU 观测；将主存、参考库存储和 GPU 显存分列。
5. 形成准确率—延迟、准确率—显存和阶段耗时图；训练型基线若有日志，再独立绘制 loss 曲线。缺失数据保留 unavailable。
